01 / 项目简介

一个插件，一套完整的聊天后台

airway-im-plugin 是基于 Airway 全栈 Go 框架开发的 IM 插件，IM 业务移植自生产级产品代码库。它把"聊天后台"这件事整体打包： 身份、会话、消息、实时推送、管理后台，全部开箱即用。

01

Airway 项目签名凭证身份

不管理密码、不做 OAuth。Airway 后端用共享密钥把 (name, uuid) 签成 HMAC 凭证，插件无状态验签，首次认证自动注册用户。支持密钥轮换与单用户凭证撤销。

02

单聊与群聊

统一会话模型：单聊规范化用户对唯一约束、get-or-create 语义；群聊支持 owner / admin / member 角色。26 位 ULID 不透明 ID，成员历史完整保留。

03

可靠消息

消息与 outbox 事件同事务落库，投递至少一次。会话内单调递增 sequence，断线后按 after_sequence 精确补拉，客户端按 message_id 去重。

04

独立 WebSocket 网关

gateway 单独部署、水平扩展：首条消息认证、10 秒认证期限、30s/40s 心跳、有界发送队列，支持同一用户多设备同时在线。

05

管理后台与审核

会话管理 API：系统状态聚合、注册用户列表与在线情况、群聊浏览、一键 mark-illegal 内容屏蔽，并向在线成员实时同步审核事件。

06

随处部署

SQLite 即可本地跑通，生产可切 MySQL / PostgreSQL。文件存储支持本地 / S3 / R2 / COS。gateway / delivery 附带 Containerfile，可容器化部署。

02 / 项目目标

给现有系统添加聊天能力, 只需一下午

接入现有账户体系

大多数项目已经有自己的账号体系。只需要在自己的系统后端，生成一个“凭证”， 即可接入 IM。

通用的客户端支持

小程序（wx.connectSocket）、 iOS / Android App、网站应用，任何支持 HTTPS 和 WebSocket 协议的客户端都能接入。

可靠的消息投递

消息先落库再响应；投递 at-least-once；断线用 sequence 补拉而不是依赖 WebSocket。

可运维、可观测

Prometheus 指标、自刷新 dashboard、健康检查、管理状态聚合、凭证撤销与密钥轮换 —— 上线需要的运维抓手随插件一起交付。

03 / 架构

三个服务，各司其职

第三方系统通过 Airway 项目的 API 接入；消息写入与实时投递分离：backend 管数据与一致性，delivery 管 outbox 投递，gateway 管长连接。

关键设计：WebSocket 投递只是低延迟优化，绝不是消息的持久副本。消息先在一个数据库事务里 落库并写入 outbox，再由 delivery 推给 gateway 扇出；离线客户端重连后通过 sequence 同步 API 补拉， 天然容忍断线、重复与乱序。
04 / 使用方式

作为插件安装进 Airway 项目

仓库根目录就是插件包（Go module github.com/daqing/airway-im-plugin）， 唯一的使用方式：安装进一个 Airway 项目，作为它的一部分对外提供 IM 服务。 plugin:install 注册 /api/v1/...、/admin/api 路由、 Go DSL 迁移与 REPL 模型，并把 gateway / delivery 两个配套服务复制到项目的 deps/im/ 下。 环境要求：Go 1.26+；本地开发用 SQLite 即可，生产可接 MySQL 8 / PostgreSQL。

安装与启动

# 1. 创建 Airway 项目并安装插件（已有项目跳过前两行）
go install github.com/daqing/airway@latest
airway new myim && cd myim
airway plugin:install github.com/daqing/airway-im-plugin

# 2. 编辑 .env（PORT=1905、DSN、IM_AUTH_SECRET、
#    IM_INTERNAL_SECRET…），初始化数据库并迁移
airway db:create
airway db:migrate

# 3. 启动三个服务（共享 IM_INTERNAL_SECRET）
#    gateway/delivery 已由 plugin:install 复制到 deps/im/ 下
airway server                       # backend  :1905
cd deps/im/gateway  && go run .     # gateway  :1910
cd deps/im/delivery && go run .     # delivery :1920

# 或：docker compose up --build

核心环境变量

变量说明
DSN数据库连接（sqlite / mysql / postgres）
IM_INTERNAL_SECRET三服务之间及第三方系统代签凭证的内部密钥
IM_ADMIN_USERNAME/PASSWORD管理后台登录凭据
GATEWAY_ALLOWED_ORIGINS浏览器端 Origin 白名单
05 / 客户端接入

接入时序：从平台账号体系到实时收发

第三方系统用自己的前端（小程序 / App / 网站）和自己的后端（PHP / Java / Python）接入 Airway IM。 前端是不可信环境，IM 通信的“凭证”只能通过第三方系统后端获取后下发。下面是完整时序。

第三方系统后端获取凭证

第三方系统后端不持有任何签名密钥。在用户登录/刷新会话时，调 Airway 项目的签发端点获取凭证，随自己的登录响应下发给前端（凭证默认 24h 过期，自动带 token_version、支持单用户撤销）。该端点在内部 listener（IM_INTERNAL_ADDR，默认 127.0.0.1:1906）上，只对服务端可达、不对公网开放。第三方平台后端与 Airway 项目不同机部署时，两者必须处在同一个内网（同 VPC / 机房，或 VPN、专线打通），由 Airway 项目方把 IM_INTERNAL_ADDR 绑定到内网网卡，平台后端经内网地址调用：

curl -X POST http://127.0.0.1:1906/internal/v1/credentials \
  -H "X-IM-Internal-Secret: <IM_INTERNAL_SECRET>" \
  -H "Content-Type: application/json" \
  -d '{"uuid":"shop1:user-42","name":"alice","nickname":"Alice","ttl_seconds":86400}'
# → {"code":0,"data":{"credential":"im1.…","expires_at":"…"}}

客户端调用 REST API：一个 Bearer 头走天下

所有 IM 接口返回统一信封 {"code":0,"data":…,"message":null}，code 非 0 即失败（10001 = 凭证无效或过期）。

// 浏览器 / App 通用：fetch 示例
const credential = "im1.<payload>.<signature>";  // 第三方系统后端下发的 im1.… 凭证
const api = (path, options = {}) => fetch("https://im.example.com/api/v1" + path, {
  ...options,
  headers: {
    "Authorization": `Bearer ${credential}`,
    "Content-Type": "application/json",
    ...(options.headers || {}),                  // 允许调用方追加头
  },
}).then(r => r.json());

// 创建单聊（同一对用户幂等，永远得到同一个会话）
await api("/conversations", { method: "POST",
  body: JSON.stringify({ kind: "direct", member_ids: [bobId] }) });

// 发消息（带 Idempotency-Key 可安全重试）
await api("/messages", { method: "POST",
  headers: { "Idempotency-Key": crypto.randomUUID() },
  body: JSON.stringify({ conversation_id: convId, content: "你好！",
                         content_type: "text/markdown" }) });

// 断线补拉：按 sequence 拉取错过的消息
await api(`/conversations/${convId}/messages?after_sequence=${lastSeq}`);

建立 WebSocket 实时通道

连接 wss://gateway-host/ws 后，10 秒内必须用第一条消息完成认证；之后保持心跳即可接收推送。

// 浏览器 JS
const credential = "im1.<payload>.<signature>";  // 第三方系统后端下发的 im1.… 凭证
const ws = new WebSocket("wss://im-gateway.example.com/ws");
ws.onopen = () => ws.send(JSON.stringify({
  cmd: "auth", opts: [credential],          // 第一条消息必须是 auth
}));
ws.onmessage = (e) => {
  const frame = JSON.parse(e.data);
  if (frame.code === 0 && frame.data === "OK") { /* 认证成功 */ }
  else if (frame.event === "message.created") {
    // 新消息事件：{message_id, conversation_id, sequence, …}
    // 若 sequence 与本地不连续，用 after_sequence 补拉缺口
  }
};
// 微信小程序（逻辑完全一致）
const credential = "im1.<payload>.<signature>";  // 第三方系统后端下发的 im1.… 凭证
const socket = wx.connectSocket({ url: "wss://im-gateway.example.com/ws" });
socket.onOpen(() => socket.send({
  data: JSON.stringify({ cmd: "auth", opts: [credential] }),
}));
socket.onMessage((res) => {
  const frame = JSON.parse(res.data);
  // 与浏览器端相同的处理逻辑
});
重连注意事项：认证失败后 gateway 以关闭码 1008 断开。客户端应退避重连； 若凭证已过期，先向 Airway 后端重新获取凭证再重连。切勿依赖 socket 恢复错过的消息 —— 重连后用 after_sequence 补拉。

06 / 管理与运维

上线之后的抓手，也都内置了

用户可视

全部注册用户、最近活跃与在线状态在管理后台一目了然，服务运行状况同步可见。

凭证撤销

凭证泄露或需要封禁用户时，一键吊销其全部凭证并断开在线连接；密钥泄露也可一键全量作废、重新下发。

内容审核

管理后台可浏览群聊与消息记录，一键标记违规内容；违规内容对用户自动隐藏，相关成员实时收到通知。

可观测

内置监控指标、可视化面板与健康探针，可直接接入主流监控系统，运行状况随时掌握。

水平扩展

三个服务都支持水平扩展，用户量增长时加实例即可，无需停机迁移。
